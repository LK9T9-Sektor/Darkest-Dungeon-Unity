# WPF: «Арена 1×1» — one-shot атака с фидбеком урона

- **Кнопка АРЕНА 1×1 в главном меню** → чисто визуальный экран 1×1: слева Crusader, справа
  Highwayman (idle-циклы), кнопка АТАКА. Ядро боя не участвует — экран проверяет цепочку
  «проиграть атаку → показать реакцию цели» перед подключением настоящих событий боя.
- **One-shot воспроизведение**: `SpinePlayer.Play(name, loop: false)` + событие
  `AnimationCompleted` (один раз, отложено до конца `Update` — из обработчика можно синхронно
  менять контент); в `SpineHeroControl` — DP `Loop` и DP `AnimationCompletedCommand`.
- **Оркестрация в VM (слоями, как в Unity)**: «АТАКА» ставит base-слот в ударную позу
  `AttackSword` и запускает поверх оверлей-скилл `Smite` (1.867 с, след меча); по завершению
  оверлея атакующий возвращается в `Idle`, оверлей скрывается, цель получает красный флеш +
  попап `-6` (стили по мотивам карточки дуэли), кнопка блокируется на время анимации (`CanExecute`).
- **Фикс: нулевая длительность one-shot** — `Attack*`-сеты героев измерены как заглушки
  (`duration=0`,4 кости): условие завершения рантайма никогда не срабатывало и кнопка зависала.
  В `SpinePlayer.Update` добавлен guard (armed-one-shot c `EndTime <= 0` завершается на первом
  тике); есть тест на реальном `AttackSword`.
- **Контент-линки Effects-скиллов**: `tools\spine-demo-content.ps1` теперь линкует и
  `<Hero>\Effects\<Skill>` (настоящие таймовые скилл-анимации: Smite/StunningBlow/… самодостаточны —
  skel+atlas+png в одной папке); `SpineDemoContent.props` перегенерирован:335 сетов /1005 линков
  (было197/591). Селектор SPINE TEST пополнился скилл-сетами.
- **Лог**: действия арены пишутся существующим файловым логгером в `Logs\duel.log`
  (`arena: opened/attack started/attack completed`) — шаг к записи игровых событий по
  `docs\SPEC_GAME_EVENTS.md`.
- Hit-скелета у героев нет — урон показываем флешем/попапом, как и решено для первого шага.

## 1. Почему легаси-риг такой: 3 камеры, «островки», дробные размеры

Три причины, по которым легаси (`Dungeon.unity`) разнёс UI и персонажей в разные места и разного
размера:

1. **FOV-зум ↔ перспектива.** ТЗ продакшна требует «зум-драмы» при касте скилла — перспективная
   камера меняет FOV, и картинка эффектно деформируется (передний план растёт сильнее фона).
   UI (кнопки, ХП-бары, карта) рендерится ортокамерой, иначе при зуме летел бы в лицо. Поэтому
   UI статичен (своя камера), мир динамичен (своя камера).
2. **«Островки» координат.** Боевая `DungeonCamera` мажет **ALL** (включая слой UI) и двигается
   (пан по X, зум). UI-канвасы — `Screen Space-Camera`, привязаны к UI-камере, а сама UI-камера
   отодвинута на `(-1069, 0, -427.92)` — **за спину** боевой камеры, чтобы та их не рисовала.
   Это хак на «все слои», а не необходимость.
3. **Размеры.** UI-канвас сделан в «пикселях» 1920×1080; Spine-персонажи — в условных единицах.
   Чтобы они совпали визуально, канвас ужали скейлом `0.10693` (1080 × 0.1069 ≈ 115.5), а камеру
   поставили на дистанцию 100: `FOV 60 → высота кадра 2·100·tan(30°) ≈ 115.5`. Канвас ровно
   заполняет кадр. (Происхождение «Spine-скейл 0.01» — непроверяемо: скелеты в gitignored
   `Library\SpineAssets`.)

**Вывод:** риг из 3 камер — это стандарт для пошаговых battler-игр, но в легаси он связан с
магическими константами и хаками на слои. Чистое пересобрать можно без всего этого ада.

## 2. Согласованный продакшн-риг «в одной плоскости»

Решение (для тестовой сцены `BattleTest` и будущего cutover-вида):

1. **UI — `Screen Space-Overlay`.** Главный UI (HUD способностей, конфиг-панель, торч-индикатор)
   рисуется поверх кадра без камеры в сцене. **UI-камера удаляется**, скейл 0.1069 и орто-размер
   57.75 больше не нужны. `CanvasScaler`: `Scale With Screen Size`, reference 1920×1080.
2. **Мир — в одной точке, без мирового канваса.** Юниты — обычные `GameObject` со Spine
   (RectTransform-корень префаба вне канваса работает; Spine рендерится `MeshRenderer` и канваса
   не требует). Фон — 2D-спрайт позади юнитов. Всё на слое `Default`, в нулевых координатах.
3. **Привязанный UI — спрайты + TextMesh, а не мировой канвас.** ХП/стресс-бары — `SpriteRenderer`,
   цифры урона/статусы — `TextMesh`, положены **внутрь префаба юнита** со смещением Z `-0.1`
   (ближе к камере; Spine-шейдеры — `ZWrite Off`, сортировка по Z корректна). Бары растут вместе
   с юнитом при зуме (естественно для DD), текст не «плывёт» из-за субпикселей канваса.
4. **2 камеры в одной точке:**
   - `DungeonCamera` — Perspective FOV 60, culling mask **Default**, clear SolidColor чёрный,
     depth 0; на ней `BlurOptimized` (выключен, включается при showoff) + чистый `BattleCameraDriver`
     (FOV-зум/follow; по мотивам `RaidPartyCamera`, без легаси-статики).
   - `BlurCamera` — копия DungeonCamera (FOV/трансформ синхронизируются), depth выше (0.3–1),
     clear Depth only, culling mask **Layer 9 (Showoff)** — перерисовывает «актёра» резко поверх
     размытого мира. Слой 9 «Showoff» уже существует в обоих деревьях (`TagManager`).
   - UI-канвасы — Overlay, поэтому камер не видят и blur их не трогает.
5. **Showoff (каст скилла):** FOV-зум к 50, включить blur на DungeonCamera, вынести актёра на
   Layer 9 (BlurCamera рисует его резко), восстановить после каста. Требует рабочий blur-шейдер:
   `MobileBlur.shader` в репо не найден — взять из `Assets\Shaders\ImageEffects`
   (`BlurEffectConeTaps` и т.п.) или добавить аналог.
6. **Свет.** Герои на `SkeletonLit` (vertex-lit) — без света тёмные. Варианты (решение ниже):
   - Directional light + яркий `Ambient Color` (в `Window → Rendering → Lighting`);
   - либо перевод материалов персонажей на unlit `Spine/Sprites/Unlit` (в комплекте Spine Runtime).
7. **Фон** — статичный спрайт из `Resources\Dungeons\<area>\` (`room_wall.*`/`corridor.*`) позади
   юнитов; загружается через `Resources.Load<Sprite>`.
8. **Торч-индикатор** — элемент HUD (иконка пламени + полоса/число), косметика; значение торча
   уже управляет статами в ядре (`DuelController`). Факельного затенения юнитов в легаси нет —
   копировать нечего.
9. **Поле в фокусе камеры.** Юниты нормализуются по высоте в рантайме (`BattleUnitView.TargetHeight`),
   центр поля = точка фокуса камеры — устраняет «юниты не попали в камеру».

## 3. Дельты к текущей реализации тестовой сцены

| Сейчас (Stage-1) | Станет (риг) |
|---|---|
| Мировой канвас `Battlefield` (scale 1) | Убрать; юниты — `GameObject` + Spine на слое Default |
| Бары — `Image` (канвас) в `BattleUnitView` | Бары — `SpriteRenderer` в префабе юнита, Z −0.1 |
| Попапы — world-канвас `Text` (`BattlePopupLayer`) | Попапы — `TextMesh`, над юнитом |
| 1 орто-камера | 2 перспективные (Dungeon + Blur, Layer 9) |
| Нет света | Directional + Ambient (или unlit) |
| Нет фона | Статичный спрайт `Resources\Dungeons\<area>\` |
| Нет showoff | FOV-зум 50 + blur + Layer 9 |
| Нет торч-индикатора | HUD-элемент (иконка + полоса) |
| HUD/конфиг — Overlay | остаётся Overlay |

Затрагиваемые файлы: `BattleUnitView`, `BattlePopupLayer`, `BattleFormationView`, `CoreBattleDriver`,
`BattleHud`, `BattleTestConfigPanel`, `BattleTestSceneBuilder` (риг-префаб), новый `BattleCameraDriver`.

## 4. Открытые решения (зафиксированы до реализации)

- **Канвас-фри полностью** (по схеме выше) vs «пока чинить камеры, оставить канвас-подход».
  Рекомендация: канвас-фри — проще и совпадает с анализом.
- **Showoff** (blur + зум + Layer 9) — сразу в этой итерации или отдельным шагом с превью-чекпоинтом.
- **Свет** — Directional + Ambient (оставить `SkeletonLit`) или перевод героев на unlit в тесте.

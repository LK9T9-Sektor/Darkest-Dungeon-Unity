# Unit info overlay: лобби и бой

`UnitInfoOverlayView` — единый лист информации о юните. В лобби он работает как редактор
загрузки героя, в бою — как окно информации по ПКМ. Поведение задаётся не режимом-флагом, а
полиморфными capability-свойствами view model.

## Правила по типам юнитов

| Возможность | Лобби, герой | Бой, герой | Бой, монстр |
| --- | --- | --- | --- |
| Имя: редактировать/рероллить | да | да | нет |
| Скиллы: выбирать | да | нет | нет |
| Лагерные скиллы: выбирать | да | нет | нет |
| Скин: менять | да | да | нет |
| Стрелки смены класса | да | нет | нет |
| Номер позиции | да | нет | нет |
| Портрет в нижнем блоке | да | нет | нет |
| Reroll тринькетов | да | нет | нет |

Нижний блок показывается, только если в нём есть хоть один видимый элемент. У боевого героя
остаётся одна кнопка скина; у монстра блок скрыт полностью.

## Данные боя

Источник — живой `DuelUnitViewModel`, а не класс из лобби:

- HP текущее/максимум и стресс;
- скорость, урон, ACC, CRIT, dodge, protection;
- все сопротивления;
- имя, класс, ранг;
- все боевые скиллы класса; выбранные (`CombatSkills`) — золотые, остальные видны серыми;
- все лагерные скиллы класса; в бою первые четыре показаны выбранными, остальные серыми;
- ряды скиллов и лагерных скиллов всегда резервируют ширину под семь плиток, но пустые
  плитки-заглушки не создаются; высота одной строки сохраняется даже при пустом списке;
- квирки и надетые тринькеты, если они есть в снимке;
- болезни — три пустых слота.

Имя меняется только в UI и на бой не влияет; карточка юнита обновляется сразу. У монстров имя
read-only.

## Spine и fallback

Для героя каталог Spine ищет `Idle` по class id. Если каталога или каталога контента нет,
`IdleContentDirectory` остаётся пустым, `SpineHeroControl` не создаётся, а в основной области
показывается portrait fallback. Ошибка отсутствующего Spine не всплывает исключением.

## Закрытие

Оверлей закрывается кнопкой `X`, клавишей Esc и кликом по затемнению. В бою затемнение
перекрывает весь экран, поэтому клики по полю боя не проходят.

## Точки расширения

- `ViewModels/UnitInfoViewModelBase` — capability-контракт, по умолчанию read-only.
- `ViewModels/BattleUnitInfoViewModel` — адаптер боевого снимка; `BattleHeroInfoViewModel` и
  `BattleMonsterInfoViewModel` переопределяют доступные действия.
- `Views/UnitInfoOverlayView` — общая разметка; `HeroIdentityView`, `HeroCharacterControlsView`,
  `HeroTrinketsEditorView` и `SkillScrollView` принимают capability-флаги.
- `Views/SkillScrollView` — `MaxRows` ограничивает высоту, `ReservedSlots` держит ширину под N
  плиток без создания элементов-заглушек.
- `Views/DuelBattleView` — ПКМ по юниту открывает оверлей вместо старого `StatsOverlay`.

# PLAN.md — активный план (исходный текст)

## Осталось: ручная проверка

Код, тесты и документация готовы; автопроверки зелёные. Осталась проверка поведения в игре и
replay. Новых правок кода по этому плану не требуется.

### Что проверить

1. [ ] **Новый рейд без боя на входе.** Запустить игру, начать новый рейд из имения и убедиться,
   что стартовая `Entrance`-комната пустая: нет боя с `ancestor_small_D`, отряд просто появляется
   в комнате.
2. [ ] **Старый сейв.** Загрузить `DarkestSave1` (создан до фикса) и убедиться, что бой на входе
   там ещё есть — это ожидаемо; сейв уже содержит encounter. Для чистой проверки нужен новый рейд.
3. [ ] **Collector replay.** Запустить WPF с указанным run:

   ```powershell
   $env:DARKEST_CAPTURE_RUN='D:\(!)Unity\Darkest-Dungeon-Unity\captures\run_2026-10-21_16-59-45'
   dotnet run --project src\Wpf\Sektor.DarkestDungeon.Wpf
   ```

   Открыть «АРЕНА 1×1» → «ВОСПРОИЗВЕСТИ ЗАХВАТ». Проверить: герой с 0 HP на Death's Door
   показывает `СМЕРТНЫЙ ПОРОГ` и не выглядит мёртвым; после смерти карточка исчезает; победитель
   остаётся `—`, потому что capture оборван без `BattleEnded`.
4. [ ] **Обычный capture.** Без env-переменной WPF по-прежнему открывает самый свежий raid-run.

### Критерии приёмки

- Новый рейд не начинает бой на входе.
- Старый заражённый сейв ведёт себя предсказуемо и не считается регрессией.
- Collector replay корректно показывает Death's Door; отсутствие победителя объяснено обрывом
  записи, а не поражением.
- Env `DARKEST_CAPTURE_RUN` не ломает выбор capture по умолчанию.

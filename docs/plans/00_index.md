# 00_index.md — планы задач

Активный план ведётся в `PLAN.md` (корень репозитория). В `docs\plans\` лежат только
**незавершённые** планы:

- **отложенный** — `<ГГГГ-ММ-ДД>-<слаг>-deferred.md` (дата — момент отложения): «Состояние»
  (что сделано, что осталось, почему отложено, как возобновить) и ниже исходный план без изменений.
  Возобновлённый план возвращается в `PLAN.md`; файл в архиве удаляется.

Завершённые планы не хранятся — их держит git-история. User-visible итог записывается коротко
одним файлом в `docs\changelog\<ГГГГ-ММ-ДД>-<слаг>.md` (индекс — `docs\changelog\00_index.md`).

Правила для агентов: `AGENTS.md` (репо) и глобальный `~/.config/opencode/AGENTS.md`
(«Plan persistence»). Навигатор по документации — `docs\INDEX.md`.

## Отложенные планы

| Дата | План | Причина отложения | Файл |
|---|---|---|---|
| 2026-10-19 | Фаза 2-A: фиксированная боевая сцена (пин высоты + `UI_Overlay`) | Эталонные снимки остались на другом ПК — приёмка сетки аспектов невозможна | `2026-10-19-fixed-battle-scene-deferred.md` |

## Как отложить план

1. Перенести секцию плана из `PLAN.md` в `docs\plans\<ГГГГ-ММ-ДД>-<слаг>-deferred.md` в том же
   коммите; дата в имени и в шапке — дата отложения.
2. Дописать в начало блок-цитату: `Отложен: <ГГГГ-ММ-ДД>` (ветка, ключевые коммиты) и раздел
   `## Состояние`: что сделано и закоммичено, что осталось, **почему отложено**, что нужно для
   возобновления.
3. Ниже разделителя — исходный план без изменений (в шагах сохраняются текущие `[x]`/`[ ]`).
4. В `PLAN.md` оставить активный (или следующий) план; отложенный упомянуть одной строкой со ссылкой.
5. Добавить строку в таблицу выше.

## Как завершить план

1. Удалить файл плана (для отложенного — переименовать не нужно, просто удалить).
2. Записать user-visible итог коротким файлом `docs\changelog\<ГГГГ-ММ-ДД>-<слаг>.md` (дата —
   завершение) и добавить строку в `docs\changelog\00_index.md`.
3. Убрать/поправить ссылки на удалённый файл во всех документах.

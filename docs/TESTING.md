# TESTING.md — Как проверить в игре

Ручная проверка поведения после изменений кода. Автопроверки (`dotnet test`,
`tools\unity-compile-check.ps1`) не заменяют её: они ловят компиляцию и ссылки, а поведение
проверяется в игре.

## Правило поддержки

После любого изменения кода, влияющего на поведение игры (вынос в ядро, фиксы, новые
фичи), **дополнить этот документ в том же коммите**: добавить/обновить строку в
«Что проверить после изменений» и, если затрагивается новая область, — чек-лист.
Не описывать косметику; достаточно краткого сценария и ожидаемого результата.

## Как запустить

- Активная версия: `unity\` (Unity 6000). Легаси: `unity-2017\` (Unity 2017.4).
- Плагины ядра (gitignored): `pwsh tools\unity-compile-check.ps1 -ProjectPath unity -Provision`
  (собирает Lan + Content + Ui и доставляет DLL/PDB в `Assets\Plugins\Internal`).
- Локальный `steam_appid.txt` создаётся автоматически; для Photon нужен AppID из
  `PhotonServerSettings.asset` и доступ к облаку Photon.
- Запуск: открыть проект в редакторе и нажать Play, либо `pwsh tools\unity-dev-run.ps1`.

## Где смотреть логи

- Консоль Unity / `Logs\Editor.log` — диагностические `[DD]`-логи:
  - `[DD] [MANAGER]` / `[DD] [DATABASE]` — старт, загрузка данных;
  - `[DD] [SAVE]` — сейв-слоты, запись/чтение;
  - `[DD] [SCENE]` / `[DD] [ESTATE]` — смена сцен, инициализация имения;
  - `[DD] [PHOTON]` — подключение Photon (также в SESSION LOG);
  - `[DD] [UNITY-Exception]` — ошибки/исключения (должны отсутствовать после фикса).
- `SESSION LOG` (кнопка «SEND» в правом верхнем углу) — мультиплеерные события.

## Общий флоу

Лого/интро → `CampaignSelection` → сейв-слоты (создание/загрузка/удаление) →
`LoadingScreen` → имение (`EstateManagement`) → снаряжение → рейд (`Dungeon`) →
возврат в имение.

## TEST-меню (главное меню)

Кнопка **«ТЕСТ»** справа-снизу на экране `CampaignSelection` открывает широкую панель:
слева — проверки и лог в скролле (с обрезкой), справа — просмотр контента
(категории + список + деталь: картинка/имя/источник/звук). Результаты дублируются в
консоль `[DD] [TEST] …`.

1. **Проверки (слева)** — прогнать действия по одному:
   - **Database counts** — счётчики контента (HeroClasses/Buffs/Quirks/Curios/Obstacles/Traps/
     Items/Monsters/Narration/PartyNames/HeirloomExchanges/LootTables); должны быть ненулевыми
     и совпадать с ожидаемыми (см. «Стартовая загрузка данных»).
   - **Loot tables** — таблицы добычи + типы записей из ядра (`LootMapper`); «tables/entries»
     ненулевые.
   - **Loot roll** — случайный ролл записи из лут-таблицы (`RandomSolver` по core-данным).
   - **Curio / Narration / Heirloom exchange / Party names** — данные из ядра (количество +
     пример).
2. **Просмотр (справа)**: категории **Trinkets / Curios / Diseases / Sounds** — список записей;
   клик по записи показывает деталь:
   - тринкет — картинка `Sprites/Shared/Inventory/Trinket/inv_trinket+<id>` + имя/файл;
   - курио — имя + число результатов/интеракций;
   - звук (наррация) — воспроизводится через FMOD и показывается его путь.
3. Ожидаемо: каждая проверка возвращает строку без «ERROR», лог в скролле (текст не выходит
   за экран). При баге — `ERROR: <сообщение>` и/или `[DD] [UNITY-Exception]` в консоли.

## Чек-листы по областям

### Стартовая загрузка данных (база данных)

1. Игра доходит до `CampaignSelection` без ошибок.
2. В логе `[DD] [DATABASE] Load: finished` и `[DD] [MANAGER] database loaded`;
   без `[DD] [UNITY-Exception]`.
3. Ключевые счётчики: `heroClasses=15`, `effects=952`, `buffs=1801`, `quirks=163`,
   `party names=186`, `heirloom exchanges=12` (могут слегка отличаться от версии данных).

### Сейв-экран (CampaignSelection)

1. Слоты создаются, если сейвов нет (1 «Darkest», 2 «Middle»), либо показывают
   существующие.
2. Пустой слот: клик открывает ввод имени; клик мимо/Enter/повторный клик по слоту
   создаёт сейв (пустое имя → дефолтное `Campaign N`); Escape полностью отменяет
   без создания (слоты разблокируются). UI не залипает.
3. Ввод имени (если раскладка позволяет) создаёт сейв; загрузка по клику →
   `LoadingScreen` → сцена.
4. Крестик удаления удаляет сейв.
5. Заполненный слот загружается даже во время именования другого слота.
6. Повторное открытие окна сохранений во время именования (клик по кнопке кампании
   до завершения/отмены ввода) не должно блокировать UI: после повторного слайда
   заполненный слот загружается по клику, слоты кликабельны.

### Кампания / имение (EstateManagement)

1. Загрузка сейва → город и постройки на месте, нет чёрного экрана.
2. В логе: `[DD] [ESTATE] Awake: ... [8]=NomadWagonWindow`, `[DD] [ESTATE] Start:
   finished`, `[DD] [ESTATE] LoadEstateEvent: finished`.
3. Открываются окна зданий: Abbey, Blacksmith, Guild, Sanitarium, StageCoach,
   Statue, Tavern, NomadWagon (обмен реликвий — `HeirloomExchange` из ядра).
4. Окно обмена реликвий: выбор типа (Up/Down), изменение количества, отображение
   курсов (из `HeirloomExchangeMapper` ядра).

### Рейд / подземелье (Dungeon)

1. Снаряжение и выход в рейд проходят; карта подземелья генерируется.
2. В подземелье встречаются **курio**: клик даёт результаты (Loot/Quirk/Effect и
   т.д.); использование предмета на курio — `ItemInteractions`. Данные из ядра
   (`CurioCsvParser` по `Curios.csv`).
3. Препятствия/ловушки/двери ведут себя как раньше (`Prop`-иерархия из ядра).
4. Добыча выпадает по лут-таблицам и бонусам за темноту (`LootDatabase` из ядра):
   после боя/сундуков приходит loot из `loot_tables`/`darkness_bonuses` (типы записей
   item/table/trinket/journal корректно раскладываются).
5. Сейв внутри рейда и загрузка: позиция/курio/пропы восстанавливаются
   (`Prop`/`Curio` сериализуются через `IBinarySaveData` из ядра).

### Наррация / звук

1. При входе в город (`town_visit_start`) и в рейд (`loading_screen_start` /
   `combat_start`) играет аудио-наррация.
2. События наррации и их ограничения считаются из ядра (`NarrationMapper` +
   `NarrationAudioEvent`): повторные события не спамятся (max_occurrences).

### Мультиплеер (Steam / Photon)

1. «Multiplayer» → меню выбора провайдера (Steam/Photon; стрелки + Enter, Esc —
   отмена).
2. Photon: открытие списка комнат, смена региона (Next/Prev), Play — случайный
   поиск/создание комнаты, создание именованной комнаты, подключение второго
   клиента.
3. Steam: создание сессии (Play — host), ввод lobby ID в слот, копирование ID
   (панель Steam Lobby ID).
4. Все события подключения/сбои видны в SESSION LOG: «Connected!»,
   «Disconnected!», join/create/fail комнат, смена региона.

### UI-оверлеи (runtime-меню)

1. SESSION LOG: кнопка «SEND»; окно 900×540, крупные шрифты (тело 22, заголовок 28,
   текст 20), скролл до последних строк.
2. Настройки (шестерёнка): громкость музыки/SFX, выход в главное меню.
3. Провайдер-меню и Steam Lobby ID панель отображаются и работают.

### Тест-бой (FightTester)

Оба Unity-проекта (`unity\` и `unity-2017\`); данные и вся логика — чистое ядро
(`Core.Data` + `Core.Duel\Fight\FightSession`).

1. Вход: TEST-меню (кнопка «ТЕСТ» на `CampaignSelection`) → **«Fight tester»**.
2. Конфигурация: 8 слотов (герои — верхние ряды, монстры — нижние); клик ЛКМ по слоту
   перебирает «пусто → герой → монстр», ПКМ — в обратную сторону; под слотами — seed
   (стрелки влево/вправо), режим «ИИ»/«Игра», кнопка FIGHT.
3. FIGHT → экран боя: герои слева, монстры справа, по 4 слота; на карточках — HP (с
   изменением после удара) и стресс; лог внизу (строки `[Round N] ...` с атаками/хилами/PASS).
4. Режим «Игра»: ход активного героя ожидает ввода — клик по скиллу подсвечивает цель,
   клик по цели выполняет ход; PASS ходит бездействием; AUTO включает автобой (ИИ и за героев).
5. Конец боя: баннер «<сторона> — победитель»; крестик (X) закрывает и возвращает в конфигурацию.
6. Детерминизм: один и тот же seed даёт одинаковый сценарий (поведение монстров не меняется).
7. Ожидаемо: ни одного `[DD] [UNITY-Exception]` в консоли; лог не уходит за экран.

### Десктоп-клиент WPF (`dotnet run` из `src\Wpf\Sektor.DarkestDungeon.Wpf`)

1. Запуск → главное меню (заголовок «ВЫБЕРИТЕ РЕЖИМ», две кнопки по центру: VS AI, MULTIPLAYER);
   крестик в меню закрывает приложение. Окно ресайзится — раскладка адаптивная (занимает всё пространство).
2. VS AI → лобби выбора героев без Steam: две переиспользуемые панели рядом — **#1 Player** и **#2 AI**,
   каждая — карточки героев в раскладке боевого поля: портрет/класс, стрелки вверх/вниз для смены
   класса, панель статов, скиллы (все, кроме Move/Pass) с тултипами по ховеру, квирки + «⟳».
   «Reroll AI» — быстрый рандом слотов ИИ; «Start Battle» внизу. Панели замощаются по ширине.
   «Start Battle» открывает бой в раскладке поля (ранги лицом друг к другу, порядок хода сверху).
   ИИ ходит сам (~0.5 с на ход) и ведёт себя как в DD: хилер (Vestal/Plague Doctor/Occultist) лечит
   самого раненого союзника (<50% HP), прочие атакуют случайно/по отметке; выбор детерминирован от
   сида сессии. Черты влияют на статы (например, «tough» +10% к макс. HP).
3. MULTIPLAYER → лобби мультиплеера: панель #1 Player, статус ожидания по центру, внизу
   session id + Host/Join/Copy ID. После Host виден ID комнаты и счётчик «Waiting mm:ss»;
   второй клиент Join по ID — **оба** переходят в бой одновременно (хост больше не зависает в ожидании).
   Крестик-возврат выходит в меню.
4. Боевой экран — адаптивная раскладка:
    верх: слева квест-панель с крестиком Retreat (крестик прибит к верху-левому углу контрола, нет
    пробела сверху; контрол не растягивается на всю ширину; внутри только текст квеста — раунд и имя
    ходящего туда не выводятся); по центру факел — сверху стрелки ◀ / глиф пламени / ▶ (пламя затеняется
    каждые 25 ед.: 0 — тёмно-серое, выше — желтее и светлее), ниже цифра раунда в кружочке крупным
    жёлтым текстом, под ней — имя ходящего персонажа цветом его команды (красный — своя, синий — враг);
    справа TURN ORDER — тайлы всей последовательности раунда (захвачена в начале раунда, поэтому полоса
    не сворачивается и не прыгает, ходящий не пропадает и держит белую рамку весь свой ход; мёртвые
    тайлы гаснут на месте). В тайле: имя сверху по центру, ниже разделённая рамкой зона под будущую
    иконку персонажа, внизу впритык к границам — скорость (слева) и нароленная инициатива (справа);
    красная/синяя рамка по командам, белая у ходящего.
    центр: карточки юнитов прибиты к низу поля с небольшим нижним отступом (~12 ед.), сохраняют
    естественные пропорции (не сплющиваются), пробел между отрядами; красные/синие рамки команд,
    всплывающий урон; отряд игрока слева-направо рангами 4→1 — фронт (ранг 1) у центра лицом к врагу,
    вражеский отряд — 1→4. Карточка — контейнер из двух блоков: сверху вертикальная карточка персонажа
    (имя по центру, ранк прибит к углу без отступов — герои верхний правый, враги верхний левый; центральная
    область-«арт» замощена полностью; баффы/дебаффы слева-направо, сверху-вниз; внизу имя класса под
    разделителем — над HP/стрессом), снизу отдельный контрол статусов: HP-полоска на всю ширину +
    значение по центру, стресс-полоска на всю ширину + значение (у заполненных квадратиков стресса
    белая обводка; пустые — серые) и у правого края вертикальные полоски действий (белая — персонаж ещё
    не ходил в раунде, серая — уже походил; несколько — если способность даёт несколько ходов).
    Имя героя канонично соответствует классу (Plague Doctor → Paracelsus, Highwayman → Dismas и т.д.).
    низ: слева один объединённый контейнер — сверху полоса ходящего персонажа (квадрат портрета +
    имя/класс; 4 способности-квадрата, внутри только слот под картинку, имя снизу: доступная — жёлтая
    рамка, недоступная — серая с серым затенением, выбранная — светлая; MOVE — квадрат с ⇄; PASS —
    узкий вертикальный прямоугольник с красной рамкой и красным X), снизу — DD-панель статов: статы
    одним контролом в 2 колонки (HP cur/max, Stress cur/max, ACC, CRIT, DMG мин-макс, DODGE, PROT, SPD),
    справа контрол снаряжения (глифы мечей/щита + уровни + вытянутые слоты) и контрол тринкетов
    (мешочек + 2 слота); портрет/имя/класс в статах не дублируются.
    по центру — тултип при наведении на юнита (появляется только при ховере, пустым экранное место не
    занимает; на всю высоту панели, адаптивный, скроллится, с секцией SKILLS).
    справа — лог/инвентарь/карта + вертикальный столбец кнопок-глифов у правого края (снизу вверх:
    INVENTORY, MAP, LOG; текст убран). Карта пока показывает единственный квадрат по центру, контент не
    выезжает за границы.
    Правый клик по юниту — лист статов со всеми скиллами/резистами/квирками; наведение на скилл —
    стилизованная подсказка с уроном/меткостью/критом/хилом и рангами. Лог крупнее и шире.
    Порядок хода по правилам DD: инициатива = скорость + бросок, первым ходит не всегда игрок 1.
    Превращение Абоминации не роняет клиент.
5. Мультиплеер-лобби: счётчик «Waiting mm:ss» тикает, пока соперник не вошёл; transport
   обрабатывает события (проверяется host/join вторым клиентом по шагу 3).

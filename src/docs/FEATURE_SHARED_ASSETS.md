# FEATURE_SHARED_ASSETS.md — Общие ресурсы для двух деревьев и десктопа

## Цель

Единый источник ресурсов (скелеты, картинки, звук), переиспользуемый в `unity\`, `unity-2017\` и
десктоп-клиенте (`FEATURE_DESKTOP_CLIENT.md`). Один источник — правка в одном месте.

## Как ведёт себя Unity (ограничения)

- Unity импортирует только файлы внутри `Assets` проекта; внешняя папка не видна `Resources.Load`.
- На импорте Unity генерит `.meta` со случайным GUID; два проекта в одной физической папке — коллизии
  `.meta` (ловушка junction'ов).
- Игра data-driven: всё грузится через `Resources.Load`/по имени, не по GUID → **копии с разными GUID
  в разных проектах безопасны**.

## Механизм: copy-sync

```
content\    (трекается, малое)  data\ локализация\ шрифты\  → unity\Assets\Resources\... + unity-2017\Assets\Resources\...
assets\     (локально, gitignored)  spine\ sprites\ audio\ fmod\  → unity\Assets\Sprites|Audio|StreamingAssets + unity-2017\…
```
- **`tools\sync-assets.ps1`** — зеркалит `content\`+`assets\` в оба проекта (по хэшам, копирует только
  изменённое); запуск перед `compile-check.ps1`/сборкой.
- Каждый проект импортирует **свои копии** → свой `.meta` → ноль коллизий GUID.
- **Десктоп** читает `content\`+`assets\` напрямую (без Unity и без синка).
- Правка: изменили источник → синк → реимпорт в Unity.

**Почему не junction/symlink:** не версионируются git'ом и дают гонки `.meta` при двух проектах.

## Состав

- **Шарится:** spine-данные (2.3), спрайты (в т.ч. часть UI-спрайтов для десктопа), аудио/FMOD-банки,
  контент-данные (JSON/DSL/XML), шрифты.
- **Остаётся в проектах:** Prefabs, Scenes, Materials, Shaders, FMOD-кэш, импорт-настройки.
- **Аудио на десктопе:** банки переиспользуемы, но воспроизведение в WPF — через FMOD Studio C# API
  (net); в PoC пропускаем.

## Gate

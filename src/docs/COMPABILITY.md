Совместимость с Unity 2017.4 (.NET 4.6)
При сборке чистого C# ядра (папка src/) для использования в Unity 2017.4 необходимо учитывать особенности старого Mono-рантайма. Ниже приведены общие рекомендации, которые помогут избежать ошибок связывания типов и проблем с отладкой.

1. Перенаправление типов и фасады .NET
Проблема: В Unity 2017.4 встроенный Mono не полностью поддерживает перенаправление типов из .NET Standard в .NET 4.6. Это проявляется в ошибках вида MissingMethodException или TypeLoadException при вызове методов из System.Collections.Generic и других базовых пространств.

Решение:
Скопируйте DLL-заглушки (фасады) из папки установленной Unity в ваш проект.
Обычно эти файлы находятся по пути (относительно корня Unity):
Editor/Data/MonoBleedingEdge/lib/mono/unityjit/Facades/
(или аналогичная папка для профиля 4.5/4.6, например, mono/4.5/Facades).
Скопируйте все файлы .dll из этой папки в каталог Assets/Plugins/Internal/ (или туда, где лежит ваша собранная библиотека ядра).
Это даст Unity правильные ссылки на системные сборки и устранит конфликты типов.
Важно: Если вы используете более новую версию Unity (2018+), этот шаг, скорее всего, не потребуется. Проверьте актуальность рекомендации для вашей версии.

2. Настройка файла проекта (.csproj) для сборки ядра
Чтобы собранная библиотека корректно работала в старом Mono, в файле .csproj для проекта src/ следует указать параметры, совместимые с Unity 2017.4:
TargetFramework – используйте netstandard2.0 (это максимальная версия, поддерживаемая Unity 2017.4).
LangVersion – ограничьте версию языка C# до 7.3 (более новые конструкции могут не компилироваться старым компилятором).
DebugType – установите full (старый Mono не понимает portable PDB, поэтому требуется полный формат отладочных символов).
Пример базовых свойств (без привязки к конкретным путям):

<PropertyGroup>
  <TargetFramework>netstandard2.0</TargetFramework>
  <LangVersion>7.3</LangVersion>
  <DebugType>full</DebugType>
</PropertyGroup>
Дополнительно:

Настройте пост-билд-событие для копирования собранной DLL и PDB в папку Assets/Plugins/Internal/ (или выбранную вами директорию), чтобы Unity автоматически подхватывала обновления.
Пример пост-билда (без жёстких путей, только принцип):

<Target Name="PostBuild" AfterTargets="PostBuildEvent">
  <Copy SourceFiles="$(OutputPath)$(AssemblyName).dll" DestinationFolder="..\..\Assets\Plugins\Internal\" />
  <Copy SourceFiles="$(OutputPath)$(AssemblyName).pdb" DestinationFolder="..\..\Assets\Plugins\Internal\" />
</Target>
Пути могут отличаться в зависимости от структуры вашего репозитория. Адаптируйте их под свой проект.

3. Общие замечания
Приведённые инструкции актуальны для Unity 2017.4.40f1. Для других версий Unity (более новых или старых) параметры могут отличаться.
Если вы используете Unity 2018+, вы можете смело перейти на netstandard2.1 или net472 и включить поддержку LangVersion до 9.0, отказавшись от ручного копирования фасадов.
Всегда проверяйте логи ошибок компиляции в Unity – они подскажут, требуется ли добавление фасадов или изменение настроек.
